## 1) 状态与续写一致性规则（State & Continuation Consistency）

### 适用场景
- 项目类：多阶段实现、跨会话接力、子代理协作
- 自动化类：cron 持续运行、失败恢复、重试链路
- 调研类（长链）：多轮检索/提炼/回写

### 规则定义
- 同一 run 只允许一个续写原语（session / previous_response / conversation 等互斥）。
- 状态承载策略互斥，冲突即 fail-fast。
- 恢复事件必须记录：continuation_authority / state_source / merge_policy（会话来源收据化）。

### 规则效果
- 避免状态双主权导致的语义漂移、错链、重复执行。
- 提高故障定位效率（单一状态真相源）。
- 增强跨会话可追溯性与复盘可复算性。

### 可能负面影响
- 早期会增加“显式失败”数量（过去隐性容错被收紧）。
- 老流程改造成本上升。

### 吸收候选（合并来源）
- R23 / R45 / R77 / R85
- continuation authority / session provenance 相关候选

## 2) 中断恢复与副作用安全规则（Interrupt/Reentry & Side-Effect Safety）

### 适用场景
- 项目类：会写文件/发消息/调用外部系统的任务
- 自动化类：重试、恢复、故障回放
- 高风险执行链：审批/外发/不可逆操作

### 规则定义
- interrupt 前仅允许可重放动作；不可逆副作用后置至恢复分支。
- 所有不可逆副作用必须带 idempotency_key，并写入 side_effect_ledger。
- 仅在合法重入条件下允许重放（同 thread、恢复语义一致、幂等键有效）。
- 审批权以 outer-run 为准，防止 nested/handoff 审批语义漂移。

### 规则效果
- 降低恢复重放造成的重复副作用事故。
- 将“可恢复”升级为“安全可恢复”。
- 统一审批与重入边界，减少分层执行错配。

### 可能负面影响
- 执行链复杂度上升（账本/幂等键/恢复检查）。
- 延迟上升，尤其高频小任务。

### 吸收候选（合并来源）
- R24 / R48 / R60 / R78 / R86
- Interrupt Reentry Side-Effect Guard（已建议转正）

## 3) 完成判定与流式闭环规则（Completion & Stream Closure）

### 适用场景
- 项目类：明确交付门槛和验收状态
- 自动化类：防“假完成”与静默失败
- 流式/长链执行：streaming + interruptions + handoffs

### 规则定义
- 完成声明必须满足三层闭环：
  1. transport_done
  2. decision_closed（interruptions=0，审批闭环）
  3. visibility_closed（critical 即时可见，operational 不超预算）
- 流式任务必须通过 tail-gate（流尾完成门）才可宣布完成。
- final_output 仅是展示面，不等于闭环完成。

### 规则效果
- 大幅降低“有输出=完成”的误判。
- 改善交付可信度与失败可见性。
- 便于跨代理链路统一完成语义。

### 可能负面影响
- 尾延迟增加（尤其 stream-heavy 任务）。
- 过严阈值可能导致“完成判定过慢”。

### 吸收候选（合并来源）
- R37 / R64 / R67 / R82
- Completion & Visibility Closure（已建议转正）

## 4) 输入歧义与高风险动作前置规则（Ambiguity & Destructive-Op Guard）

### 适用场景
- 项目类：发布/删除/覆盖写/迁移等高风险动作
- 调研类：目标边界模糊、需求语义不完整
- 自动化类：无人值守但可能触发外部副作用

### 规则定义
- 命中歧义阈值时，必须触发澄清。
- 破坏性操作执行前，必须先 dry-run / 影响范围预览，再确认。
- 高风险默认 blocking，必要时人工 checkpoint。

### 规则效果
- 前移阻断误操作，减少返工与事故成本。
- 让“问不问问题”从主观习惯变为成本优化策略。

### 可能负面影响
- 回合数上升（体感变慢）。
- 阈值过敏会导致“过问”。

### 吸收候选（合并来源）
- R80 / R81
- Consent-before-Irreversible / destructive preview 相关候选

## 5) 证据收据、主张治理与记忆预算规则（Evidence Receipt, Claim Governance & Memory Budget）

### 适用场景
- 调研类：数字/比例/性能结论输出
- 自动化类：高频循环、成本控制、记忆污染防治
- 项目类：验收报告、回归验证、SLO评估

### 规则定义
- 高影响主张（尤其数字/比例）必须绑定来源收据（source/log/path/hash/tool_output_id）。
- 异常处理必须保留结构化证据包（RunError envelope）。
- 周期任务默认 Delta-First（先做 Phase-0 变更探针，未命中不进重推理）。
- 引入 session-type memory budget + miss escalation，避免“省 token 导致关键记忆失效”。
- 对 machine-facing 输出建立质量 SLO，避免“不可见面静默劣化”。

### 规则效果
- 抑制伪精确与无证据确定性陈述。
- 降低 token 浪费和记忆写入噪声。
- 增强跨轮复算与审计能力。

### 可能负面影响
- 收据化增加记录负担。
- 预算过紧可能损失召回；过松则成本失控。
- 指标化不当存在 Goodhart 风险。

### 吸收候选（合并来源）
- R38 / R39 / R40 / R50 / R51 / R52 / R58 / R59 / R61 / R65 / R73 / R79 / R84 / R87
- RunError Evidence Envelope / Delta-First Cron（已建议转正）

## 6) 供应链与能力面治理规则（Supply-Chain & Capability Surface Governance）

### 适用场景
- 技能安装/更新
- 外部工具接入
- hosted/local 运行面切换

### 规则定义
- 安装前必须做来源与完整性校验（install_receipt/provenance）。
- 能力面变更触发阈值审计（新增能力、权限提升、策略漂移）。
- 控制选择以威胁模型为先（threat-model-first），而非“有控制就上”。
- 出站策略采用 manifest + default-deny，防隐式数据外流。

### 规则效果
- 将风险前移到“引入前”，减少带毒上线后补救。
- 明确能力漂移与策略漂移的审计入口。

### 可能负面影响
- 上线速度下降。
- 误报高时会造成“治理疲劳”。

### 吸收候选（合并来源）
- R35 / R36 / R47 / R49 / R53 / R54 / R68 / R69 / R70 / R74 / R75 / R76

## 8) 后续优化协议（每轮学习后执行）

1. 新候选先尝试映射到现有 6 条母规则，不新增编号优先。
2. 只有在“无法归类且连续 3 轮独立证据支持”时，才新增母规则。
3. 每周执行一次冲突矩阵审计：
   - 重复约束 -> 合并
   - 空洞约束 -> 补字段
   - 相互冲突 -> 指定优先级
4. 每条母规则至少维护 1 个“负面影响监控指标”（例如延迟、误拒率、误报率、返工率）。
