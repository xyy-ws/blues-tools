## 二、核心运营场景

### 场景 1：SIEM 告警 → 自动研判 + 处置

```
① SIEM 产生告警（规则触发）
       ↓
② Shuffle SOAR 接收告警（Webhook / API）
       ↓
③ 自动去重 + 聚合（同一IP/同一事件合并）
       ↓
④ AI Agent 辅助研判（验证告警真实性，降低误报）
       ↓
⑤ 决策分支：
   ├─ 高置信度 → 自动处置（封锁IP / 隔离主机）→ 人工审批后执行
   ├─ 中置信度 → 创建 TheHive 工单 → 分析师调查
   └─ 低置信度 → 标记误报 → 记录反馈到 SIEM 规则调优
       ↓
⑥ 处置结果回写 SIEM + 工单闭环
       ↓
⑦ 运营指标更新（MTTD / MTTR / 处置率）
```

### 场景 2：新服务器上线 → 安全检查

```
① CMDB / 云平台 API 推送新资产上线事件
       ↓
② Shuffle SOAR 接收事件（触发剧本）
       ↓
③ 自动采集资产信息（IP / OS / 端口 / 服务 / 负责人）
       ↓
④ 与已有资产数据库比对（是否重复 / 是否在白名单）
       ↓
⑤ 合规检查（安全基线验证：端口开放 / 服务暴露 / 密码策略）
       ↓
⑥ 结果写入 CMDB 资产卡片（安全评分）
       ↓
⑦ 高风险项 → 创建 TheHive 工单 → 安全工程师跟进
       ↓
⑧ 运营指标更新（上线合规率）
```

### 场景 3：威胁情报消费 → 内网资产匹配

```
① 外部威胁情报推送（IP 信誉库 / 恶意域名库 / CVE 详情）
       ↓
② Shuffle SOAR 接收情报（标准化格式）
       ↓
③ 与内网资产/流量日志自动匹配
       ├─ 命中 → 触发调查剧本
       └─ 未命中 → 记录存档
       ↓
④ 调查结果写入 TheHive + 回写 SIEM
```

## 三、当前运营痛点分析

### 痛点 1：告警疲劳
- **现象**：SIEM 日产生告警量过大，分析师无法逐一处理
- **根因**：规则宽泛、误报率高、缺乏智能去重
- **影响**：真实威胁被淹没，MTTD 拉长

### 痛点 2：研判效率低
- **现象**：每次告警需要分析师手工查询多个系统（SIEM + DNS + AD + CMDB）
- **根因**：系统孤岛，信息分散，缺乏自动化关联
- **影响**：MTTR 居高不下人力紧张

### 痛点 3：响应链路不闭环
- **现象**：处置后不回写 SIEM，规则不更新，同类告警反复出现
- **根因**：缺乏自动化工单闭环 + 规则反馈机制
- **影响**：运营效率低，告警重复率居高

### 痛点 4：混合云环境覆盖不全
- **现象**：云平台告警和线下网络告警分开处理，缺乏统一视图
- **根因**：云平台和本地安全工具未打通
- **影响**：攻击链路跨云时无法关联分析

### 痛点 5：运营指标不可见
- **现象**：无法量化团队安全运营效果（MTTD / MTTR / 人均处置量）
- **根因**：缺乏统一指标采集和可视化平台
- **影响**：管理层无法评估运营 ROI

## 五、运营指标体系

### 5.1 核心 KPI

| 指标 | 定义 | 目标值 | 采集方式 |
|------|------|--------|---------|
| MTTD（平均威胁检测时间）| 告警产生 → 确认的时间 | < 30 分钟 | SIEM 时间戳 |
| MTTR（平均响应处置时间）| 告警确认 → 闭环的时间 | < 4 小时 | 工单系统 |
| 告警总量/日 | 每天 SIEM 产生告警数 | 趋势下降 | SIEM |
| 误报率 | 误报告警 / 总告警 | < 40% | 分析师反馈 |
| 自动化处置率 | 自动处置数 / 总处置数 | > 30% | SOAR |
| 工单闭环率 | 已关闭工单 / 总工单 | > 90% | TheHive |
| 平均每事件人力 | 处置一个事件平均工时 | 趋势下降 | 工时统计 |

### 5.2 安全态势指标

| 指标 | 说明 |
|------|------|
| 告警趋势（周/月）| 环比告警量变化 |
| TOP 告警类型分布| 哪类告警最多（暴力破解 / 恶意软件 / 钓鱼等）|
| 高危告警处置率| P0/P1 告警及时处置比例 |
| 横向移动检测率| 内网横向移动相关告警占比 |
| 资产覆盖率| 纳入监控的资产 / 总资产 |
| 日志源完整率| 预期日志源实际接入比例 |

## 九、风险与约束

| 风险项 | 影响 | 缓解措施 |
|--------|------|---------|
| 系统集成复杂度高 | 项目延期 | 分阶段交付，每阶段有可独立验收成果 |
| 日志源接入标准不统一 | 归一化质量差 | 制定统一字段规范，编写接入验收标准 |
| 人工审批节点可能超时 | 响应延迟 | SLA 告警 + 自动升级机制 |
| 云平台 API 权限申请周期长 | 影响接入进度 | 提前申请云平台只读账号权限 |
| 运营团队对自动化信任不足 | 推广阻力 | 先用辅助模式（建议而非自动执行），建立信任后再推进自动 |
